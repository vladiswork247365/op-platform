# HH Autopilot — автономная система поиска, анализа и обработки вакансий

Система по расписанию получает вакансии из **HeadHunter** (`api.hh.ru`, работает
для hh.ru и hh.kz через `area`), исключает дубли, дёшево фильтрует, отправляет
подходящие в AI-анализ, сравнивает с резюме, считает Match Score, формирует
сопроводительное письмо и — в режиме PRODUCTION — отправляет отклик через
официальный интерфейс площадки. Всё видно в веб-панели; исключения попадают в
очередь «Требует внимания». По умолчанию система работает в безопасном режиме
**DRY RUN** и ничего не отправляет, пока вы явно не включите PRODUCTION.

> **Принцип:** система работает сама — пользователь контролирует только исключения.

---

## Стек (простой, дешёвый, без лишнего)

| Слой | Технология |
|------|------------|
| Backend / API | FastAPI + Uvicorn |
| Хранилище | SQLite по умолчанию (файл, без отдельной БД). `DATABASE_URL` → Postgres |
| Планировщик и воркеры | APScheduler в том же процессе (без Celery/Redis/брокера) |
| AI-анализ | Anthropic Claude (или детерминированный mock без ключа) |
| Панель | серверные Jinja2-шаблоны + чистый JS (без сборки) |
| Упаковка | один Docker-контейнер, docker-compose, healthcheck, restart policy |

Внешних сервисов для работы не требуется: с `VACANCY_SOURCE=mock` и
`AI_PROVIDER=mock` система полностью работает офлайн (для демо, тестов и DRY RUN).

## Быстрый старт

### Вариант A. Docker (рекомендуется)

```bash
cp .env.example .env          # заполните секреты при необходимости
docker compose up -d --build  # поднимет сервис с healthcheck и авто-рестартом
# панель: http://localhost:8000   health: http://localhost:8000/health
```

### Вариант B. Локально

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m scripts.deploy_check     # E2E DRY RUN + Deployment Report
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

База создаётся автоматически при старте (таблицы + настройки по умолчанию) —
отдельный шаг миграции не нужен.

## Переход в PRODUCTION (безопасный запуск)

1. Запустите `python -m scripts.deploy_check` — должно быть
   `READY FOR PRODUCTION` без критических FAIL.
2. Заполните `HH_ACCESS_TOKEN` и `HH_RESUME_ID` (нужны только для отправки
   откликов) и, при желании, `ANTHROPIC_API_KEY`; установите
   `VACANCY_SOURCE=headhunter`, `AI_PROVIDER=anthropic`.
3. В панели откройте раздел «Настройки», заполните профиль кандидата, резюме,
   пороги и сопроводительное письмо.
4. Переключите режим в PRODUCTION (кнопка на «Обзоре» или на «Настройках»).

До этого момента система только анализирует и показывает, что **было бы**
отправлено, но не отправляет ничего.

## Как работает цикл

```
source.search → дедуп (id + хеш контента) → дешёвый префильтр →
AI-анализ (резюме + профиль) → Match Score → решение MATCH/REVIEW/REJECT →
сопроводительное письмо → финальная проверка письма → отклик (или DRY RUN) →
контакты (если опубликованы) → WhatsApp (подготовка, отправка отключена) →
запись в БД + аудит + статистика цикла
```

- **Пороги** (панель): `MATCH ≥ auto_apply_min_score`,
  `REVIEW ≥ review_min_score`, иначе `REJECT`.
- **Жёсткие ограничения профиля** (например, обязательный минимум зарплаты)
  имеют приоритет над Score и могут форсировать REJECT.
- **REVIEW** и всё, что система не смогла безопасно решить, уходит в очередь
  «Требует внимания».

## Защита (реализовано)

- **Дедуп в два слоя:** уникальность `(source, external_id)` + хеш
  `компания+должность+описание` (ловит перевыложенную вакансию под новым id).
- **Идемпотентность откликов:** ключ `apply:<vacancy_id>`; успешно отправленный
  отклик не повторяется даже при рестарте воркера или позднем retry.
- **Retry с бэкоффом:** 5 мин → 15 мин → 1 ч → 3 ч, затем FAILED. Постоянные
  ошибки (4xx) не ретраятся; временные (429/5xx/сеть) — ретраятся.
- **Лимит откликов за цикл** (`PER_CYCLE_APPLY_LIMIT`).
- **Изоляция сбоев:** каждая вакансия обрабатывается в своей транзакции —
  одна ошибка не роняет цикл.
- **Self-healing:** watchdog переустанавливает пропавшие задачи и перезапускает
  планировщик; падение процесса поднимает Docker `restart: unless-stopped`.
- **Секреты только из окружения**, не в коде. `.env` в `.gitignore`.
- **Только официальные API**, без обхода CAPTCHA/антибота/лимитов.

## Health и самодиагностика

- `GET /health` — статус компонентов (API, DB, Scheduler, Worker, AI, источник,
  WhatsApp), время последнего успешного цикла, глубина очереди, число ошибок за
  24 ч. Код `503`, если какой-то компонент в ERROR.
- Ежедневный расширенный System Check (диск, память, зависшие задачи) — job
  `diagnostic`, результат в аудите и в ошибках, если система нездорова.

## Панель управления

| Страница | Назначение |
|----------|------------|
| `/` Обзор | статус системы, «за сегодня», кнопки «Запустить цикл» / «Переключить режим» |
| `/vacancies` | таблица с фильтрами (сегодня/вчера/неделя/MATCH/REVIEW/REJECT/отклик/внимание) |
| `/vacancy/{id}` | описание, AI-анализ и подшкалы, письмо, статус отклика, контакты, WhatsApp, тех.лог |
| `/attention` | очередь исключений (REVIEW, ошибки, нестандартные ситуации) |
| `/runs` | история циклов автопоиска |
| `/settings` | режим, интервал, пороги, профиль кандидата, профиль поиска, письмо |

## Расширение

- **Новый источник вакансий:** реализуйте `VacancySource` в `app/sources/` и
  зарегистрируйте в `build_source`.
- **WhatsApp:** сейчас `NOT_CONFIGURED` (по требованию). Модуль, контакты,
  статусы и идемпотентность уже на месте — достаточно добавить адаптер
  провайдера в `app/whatsapp.py`.

## Вынос в отдельный репозиторий

Проект самодостаточен (папка `hh-autopilot/`). Чтобы сделать его отдельным репо:

```bash
cp -r hh-autopilot ../hh-autopilot-standalone
cd ../hh-autopilot-standalone && git init && git add . && git commit -m "init"
```
